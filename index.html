Foundations · 01

What is a process bigraph?

A bigraph, in Robin Milner's sense, is two graphs over the same nodes at once: a place graph of nesting (what is inside what) and a link graph of wiring (what is connected to what). Vivarium borrows the idea and makes it run.

● Typed stores

Hierarchical, schema-validated state — the “place graph.” A store can hold a number, a mass with units, or another whole composite. Defined and checked by bigraph-schema.

x : P ⇀ V typed by Σ · Spatio-Flux substrates : map[concentration]

▬ Processes

Executable components with explicit input and output ports. A process never mutates state directly — it reads its inputs and returns typed deltas.

f : (inτ) → (outτ) · class Process · Spatio-Flux MonodKinetics, DynamicFBA

◈ Composites

Encapsulated sub-simulations with their own internal stores and processes. A composite is itself a process — so models nest without limit.

bridge : ext → P · class Composite · Spatio-Flux spatioflux_reference_demo
The one rule that makes it compose: processes emit typed deltas, and the runtime merges them. Numerical updates, structural rewrites (division, workflows), and scheduling all coexist under a single execution semantics. Process-Bigraph is a composition protocol, not a domain-specific simulator.

Wiring, not calling

Two processes never call each other. They are wired to the same store — one writes mass, another reads it — and the runtime is what carries the value across the wire between timesteps. That indirection is the whole trick: any process that speaks the port protocol can be swapped in, and heterogeneous timescales (a millisecond ODE next to an hour-long division event) resolve against the same shared state.

The formal object

Everything above has a precise form. Each subsystem is a process bigraph — a four-part object the paper defines exactly:

B = ( Σ, x, RT, RL ) Σ the schema (typed blueprint) · x the state (its stores) · RT the type registry (how deltas apply) · RL the link registry (which code runs each process). Separating Σ from x is what lets a model be validated, reused, and reasoned about apart from any single run.

Formalism ↔ software ↔ repos

The framework's real payoff is that the formal symbols, the Python classes, and the repositories line up one-to-one — and each has a concrete counterpart in Spatio-Flux, the microbial-ecosystem model that runs throughout the paper. Foundations · 02

The update loop, live

Here is the canonical first process from the Vivarium quick-start — a cell that grows. It is 8 lines of Python, and the widget below actually runs it in your browser so you can watch typed deltas merge into a store, step by step.

process_bigraph · Growpython
class Grow(Process):
    config_schema = {'rate': {'_type':'float', '_default': 0.10}}

    def inputs(self):   # read port
        return {'mass': 'float'}
    def outputs(self):  # write port
        return {'mass': 'float'}

    def update(self, state, interval):
        # emit a typed delta, don't mutate
        return {'mass': state['mass'] * self.config['rate'] * interval}
Interactive

Run it

step0 store · mass1.000 last delta— rate 0.10

Each Step calls update(), gets back {mass: Δ}, and the runtime merges that delta into the store. Nothing in Grow knows what happens next — a division process, an emitter, or a plot could all be wired to the same mass store, unchanged.

Formally: update() returns a typed delta δ = update(xin, Δt), and the runtime applies it by type — x′ = applyτ(x, δ). For a float that merge is addition; for a concentration it clamps at zero; for a graph it rewrites structure. Grow is the minimal case — Spatio-Flux's MonodKinetics and DynamicFBA have the exact same shape, which is why one drops in for the other without touching anything else.

Doing science · 04

Wrap → Compose → Run

Every simulator in this ecosystem earns its place the same way: it is wrapped as a typed Process, composed with others through shared stores, and run by the engine. Three moves, endlessly repeated.

◆

1 · Wrap

Point at a real simulator — COPASI, LAMMPS, an FBA model — and expose its state as inputs()/outputs() ports. The wrapper bridges the actual binary or library; it does not fake the science. This is what a viva-<tool> repo is.

◆◆

2 · Compose

Wire several wrapped processes to shared stores to form a Composite — e.g. a membrane mechanics solver pushed by a particle-based actin process, closed-loop. The composite is a new process, ready to wrap again.

◆◆◆

3 · Run

Hand the composite to the runtime for N steps. It schedules each process on its own timescale, merges deltas, and streams observables to an emitter (SQLite, Parquet, RAM) for analysis.

Doing science · 05

Templates & sites

Here is the one idea that connects the science layer to the engine: a study or an investigation is a process-bigraph template — a document with open sites (holes). Filling the holes turns it into a runnable Composite. The workbench stores the template and does the filling; the engine does the running.

template → site → fill → composite. A template fixes everything except a few named holes. Each site is a typed hole. Filling a site with a matching composite (plus its config) yields a concrete, runnable model — and leaving a site open is itself meaningful: it prunes that branch from the run. Toggle the two views below to see the same mechanism make a study and an investigation.

Under the hood this is the engine's trigger() doing pull-or-compute on the results axis (process-bigraph Tutorial 4): an open results site computes; a filled one is read from cache; branches whose sites stay open are pruned. The Studies and Investigations sections below are this same mechanism, applied.

Doing science · 06

Studies, tests & the analysis layer

A running composite answers nothing on its own. A study is one question asked of one model — a composite plus configuration, turned into a verdict, a figure, and a report card. Studies move through five phases; click one.

↑ In Templates & sites this is the Study view: the fixed analysis network with the model as its open site. Everything below — conditions, readouts, tests, visualizations — is what fills and grades that template.

Analysis · readouts

What we measure

A study declares outputs / readouts — the observables recorded each run (dry mass, growth rate, a species trajectory). They flow to an emitter and land in the study's own runs.db.

Analysis · tests

Tests as verdicts

behavior_tests turn expectations into graded PASS / FAIL / SKIP pills. A test's verdict is derived from the latest run's recorded outcome — never hand-set — so a report can never claim a pass it didn't measure.

Analysis · visualization

Figures & report cards

Each study renders named visualizations (viz/<name>.html) and a report card scoring the biological claim against literature anchors — the evidence a reviewer actually reads.

Doing science · 07

Investigations build an argument

An investigation is a set of studies that build a cumulative argument under one research question. It is the same idea as a study, one level up — a template with one open site per member study.

↑ This is the Investigation view in Templates & sites: toggle members open/filled to watch admit vs prune and pull vs compute resolve live.

Convert → trigger → pull-or-compute

The workbench lowers an investigation into a process-bigraph document and runs the engine's trigger over the results axis:

  • an open results site → the study computes;
  • a filled site → consumers read the cached handle, no rerun;
  • a prerequisite is resolved by content address — pulled from .pbg/artifacts/<hash>/ if it exists, computed if not; non-ancestors are pruned.

That is what “continue from here without rerunning the expensive upstream” means concretely — reuse a cached upstream fit, recompute only the downstream study.

investigation.yamlyaml
name: metabolism_comparison
description: Compare growth across carbon sources.
members:
  - calibrate          # the expensive fit (upstream)
  - glucose_growth     # ┐
  - succinate_growth   # ┤ each reads calibrate's cached params
  - acetate_growth     # ┘
A DAG is inferred from each study's prerequisites. Filling a member admits it to the run; leaving it open prunes it. Gating is filling, not a scheduler decision.

You rarely write this plumbing by hand. vivarium-workbench is the web UI over a workspace; viva-superpowers is a Claude Code plugin whose 14 /viva-* skills scaffold the mechanical parts — you talk biology, the agent writes the typed Python, YAML, and figures.

The ecosystem · 12

Spatio-Flux: composition in action

Spatio-Flux is the paper's reference application — and the clearest way to watch the formalism do work. It builds up a microbial ecosystem one process family at a time; at every step the pieces couple only through typed shared stores, and new behavior emerges from the composition, not from any single model. These are the models behind the paper's Figs 7–8, each a real declared composite in .

1

One site, two formalisms

A single well-mixed site, growing on a shared substrates store. Because MonodKinetics and DynamicFBA expose identical port types (f : (inτ)→(outτ)), one substitutes for the other without touching anything around it.

MonodKineticsDynamicFBA
The composition guarantee in miniature: swap the mechanism, keep the model (Fig 7b,c).
2

A community on one environment

Drop several species into one shared nutrient environment. Each declares its own metabolism, but all bind the same environmental fields through their substrates port — coupling is mediated entirely by shared state (the wiring W), never by process-to-process calls.

DynamicFBA ×NMonodKineticsmulti-timestepping
Species grow until the shared resource depletes — interaction with no direct connections (Fig 7a,d).
3

Space: the COMETS lattice

Give every lattice site its own metabolism and let neighbours exchange metabolites through DiffusionAdvection. Metabolism is local; transport is a separate process on the same fields — the classic COMETS-style alternation, expressed as composition.

SpatialDFBADiffusionAdvectionmulti-timestepping
Biomass climbs the glucose gradient; acetate byproduct is consumed behind it — reproducing within 0.1% (Fig 7e,f).
4

Motile particles

Add agents that move. BrownianMovement gives stochastic motion; PymunkParticleMovement adds Newtonian mass, velocity and collisions. A ManageBoundaries graph-rewrite inserts and removes particles at the domain edge — structure that changes at runtime.

BrownianMovementPymunkParticleMovementevent-driven rewrite
Particles diffuse and collide through continuous space (Fig 7g,h).
5

The reference metacomposite

Everything at once, in spatioflux_reference_demo. Newtonian particles each carry two internal dFBA models — ecoli1 (glucose-specialist) and ecoli2 (acetate-specialist). A ParticleExchange adapter couples particle chemistry to Monod + diffusion fields, an accumulate-mass adapter sums biomass, and a ParticleDivision rewrite splits a particle past a mass threshold.

ParticleExchangeParticleDivisioninternal dFBA ×2timed ∥ workflow ∥ rewrite
Glucose-specialists dominate early; acetate-specialists take over as byproducts accumulate — a succession no single process encodes. It emerges from the composition (Fig 8).
Every step is the same machinery — typed stores, explicit wiring W, deltas applied by applyτ, a Composite orchestrating — just more of it. Each is a real, executable composite you can open in , and the paper's figures are these exact models rendered by loom ↓.
The ecosystem · 13

The flagship: a whole cell

Everything converges in v2ecoli — a whole-cell E. coli model rebuilt in Vivarium 2. It is the ecosystem's proof that the protocol scales: 55+ mechanistic processes, from transcription to metabolism, wired into a single dividing cell.

The model wraps a large Composite (EcoliWCM) whose sub-processes each speak the same port protocol as the toy Grow above — transcript synthesis, protein degradation, two-component signalling, an FBA metabolism step, replication. An expensive parameter-fitting study runs once; downstream growth studies pull that cached fit rather than recompute it.

Because it is just another composite, it plugs into the same studies, tests, and visualizations as anything else in the catalog — and into larger composites still, like a cell coupled to a bioreactor.
